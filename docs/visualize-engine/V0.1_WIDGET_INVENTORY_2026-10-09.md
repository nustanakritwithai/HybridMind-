## 4. Visual grammar to preserve

- Dark navy gradient canvas and cards; luminous mint/blue/peach/purple accents; glass-like sticky header; deliberate depth and whitespace.
- CSS-drawn architecture / flow visualization (do not claim SVG/canvas based rendering).
- Interactive switchers provide immediate feedback; dynamic descriptions are not hardcoded screenshot illustrations.
- Clear Arabic/Thai/English mixed typography, mobile breakpoints, accessible button states and text alternative.
- Lesson → exploration → application → quiz → conclusion narrative journey.
- The future system must support both visually cohesive default templates and per-article theme tokens without asking Worker to redesign site branding.

## 5. Current limitations visible in source

| Finding | Consequence for Widget Engine | Proposed handling |
| --- | --- | --- |
| Entire 41 KB+ lesson generated as one `srcdoc` | Cannot update `box-03` without rewriting whole source | Store individual immutable widget specs/versions, render into separate slots |
| CSS/JS scoped to whole iframe (global selectors inside frame) | Global state and CSS collides if split naïvely | Namespace state and CSS by `widget_id`, use renderer-owned components |
| Uses `innerHTML` for steps from static trusted JS constants | Future insertion of LLM text can create XSS risk | Worker outputs data; renderer uses `textContent` or strict sanitization, not raw HTML |
| Bridge uses wildcard `postMessage(...,'*')` and one outer frame | Multi-widget event routing is insufficiently isolated | Per-frame IDs + capability-limited structured messages, source checks, one-way resize/navigation only |
| `allow-popups-to-escape-sandbox` present | Popup can escape sandbox restrictions | Do not allow popup escape in generated widget frames; open vetted references from trusted parent |
| Quiz answers are dynamically generated in JS | Must preserve interaction behavior | Renderer-owned quiz state machine, never worker-supplied event handler code |
| No custom widget worker or request endpoint | Prototype is not an engine | Build authenticated request API/validator/renderer behind release gates |

**Bottom line:** The source includes many reusable design ideas, but **Widget Library / A2A Worker / Sandbox / production Widget API do NOT yet exist**.
